# Weekly Production Cycle 1 — QA Failure Audit and System Hardening

Root-cause audit of the "10 Amazon Rainforest Facts for Kids" draft
(post 546, staging), treated as a permanent regression fixture rather
than a one-off correction. All findings below are grounded in direct
inspection of the actual stored post content, direct code inspection of
`related-content.php` and `class-bhp-cta-engine.php`, and direct
re-verification of sourcing against WWF's own site and USGS-adjacent
search results — not assumed from the earlier session.

## What did NOT turn out to be a defect (verified, not assumed)

- The core numbers for pink river dolphins (few freshwater species), giant otters (six-foot length), piranha mythbusting, and the ter Steege 2013 tree-species estimate all held up under direct re-verification against National Geographic, WWF, and the original *Science* study — these are not flagged.
- The Kirkus-quote-preservation and no-fabricated-schema regression suites (unrelated to this article, but part of the same session's broader QA surface) continued to pass throughout — not a false confidence signal, a real one.

**Root cause, stated plainly:** no stage of the pipeline I ran actually
verified a claim's wording against its source's actual wording — I
treated "I found a source that's roughly about this topic" as
equivalent to "this exact sentence is supported," which it is not. The
same gap applies to HTML structure and WordPress packaging: I was
producing plausible-looking output without a pass/fail gate checking it
against explicit rules. The system sections below build those gates.
